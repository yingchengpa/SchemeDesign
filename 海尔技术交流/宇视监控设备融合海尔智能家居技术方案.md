# 宇视监控设备融合海尔智能家居 — 技术方案文档

---

## 一、项目背景与现状分析

### 1.1 项目背景

海尔智能家居以家电设备为核心，当前摄像机产品采用第三方公司的成套方案，存在以下问题：

- **无自主知识产权**：音视频能力完全依赖第三方，无法自主迭代和优化
- **能力不可控**：第三方产品的功能、性能、升级节奏均受制于供应商
- **用户体验割裂**：不同厂商的设备接入方式不一致，影响整体用户体验

### 1.2 现状梳理

| 维度 | 现状 | 影响 |
|------|------|------|
| 海尔自研音视频平台 | 已启动研发，但成熟度不足，无法短期支撑大规模设备接入 | 中长期自主可控的基础，但短期无法作为主力 |
| 宇视音视频平台 | 经过大量设备验证，稳定性高，且海尔将使用宇视相机 | 可作为短期快速接入的可靠方案 |
| 合作深度 | 宇视可提供源码方式支持海尔自研平台建设 | 为中长期自主可控提供了可行路径 |

### 1.3 核心挑战

1. **短期目标**：快速、稳定地将宇视设备引入海尔智家 App，满足市场急需
2. **中长期目标**：逐步提升海尔自研音视频平台的自主权，实现核心技术自主可控
3. **衔接问题**：如何确保短期方案与中长期目标平滑过渡，避免重复建设和用户迁移成本

## 二、技术方案总览

### 2.1 方案策略：分阶段演进

采用 **"短期云云对接 + 中长期自研替代"** 的分阶段演进策略，兼顾快速上线与长期自主可控：

```
┌─────────────────────────────────────────────────────────┐
│                    整体演进路线                           │
│                                                         │
│  Phase 1          Phase 2          Phase 3              │
│  ┌──────┐        ┌──────┐        ┌──────┐              │
│  │云云对接│──────▶│混合并行│──────▶│自研主导│              │
│  │快速上线│        │逐步迁移│        │完全自主│              │
│  └──────┘        └──────┘        └──────┘              │
│  0~3个月          3~12个月         12~24个月              │
└─────────────────────────────────────────────────────────┘
```

### 2.2 方案对比

| 对比维度 | 方案A：纯云云对接 | 方案B：纯自研 | 方案C：分阶段演进（推荐） |
|---------|------------------|-------------|----------------------|
| 上线速度 | 快（1~3个月） | 慢（12~24个月） | 快（1~3个月首期上线） |
| 稳定性 | 高（宇视平台已验证） | 低（初期不稳定） | 高（先稳后进） |
| 自主权 | 低 | 高 | 逐步提升至高 |
| 投入成本 | 中 | 高 | 中（渐进式投入） |
| 过渡风险 | 无 | 无过渡 | 可控（按计划迁移） |
| 用户影响 | 无 | 无（未上线） | 最小（平滑迁移） |

**结论**：推荐方案C（分阶段演进），在满足短期快速上线的同时，为中长期自主可控奠定基础。

## 三、Phase 1：云云对接方案（0~3个月）

### 3.1 方案架构

```
┌──────────────┐     ┌──────────────┐     ┌──────────────────┐
│  海尔智家 App  │────▶│   海尔云平台   │────▶│  宇视私有云（部署   │
│  (集成宇视SDK) │     │  (API网关/鉴权) │     │   在海尔云内)      │
└──────────────┘     └──────────────┘     └────────┬─────────┘
                                                   │
                                          ┌────────▼─────────┐
                                          │   宇视摄像机设备    │
                                          └──────────────────┘
```

### 3.2 核心对接流程

#### 3.2.1 云云对接架构

| 组件 | 说明 | 部署位置 |
|------|------|---------|
| 海尔智家 App | 集成宇视播放 SDK，实现视频预览、回放等功能 | 用户终端 |
| 海尔云平台 | 负责统一鉴权、设备管理 API 网关，对前端屏蔽后端差异 | 海尔云 |
| 宇视私有云 | 宇视平台私有化部署，提供设备管理、流媒体等完整能力 | 海尔云内（独立资源） |
| 宇视摄像机 | 设备注册到宇视私有云，通过宇视协议进行音视频传输 | 用户侧 |

#### 3.2.2 关键接口设计

```
1. 设备绑定流程：
   App → 海尔云 → 宇视私有云 → 设备扫码/序列号绑定 → 返回设备信息

2. 实时预览流程：
   App(宇视SDK) → 宇视私有云 → 拉取设备实时流 → 本地解码播放

3. 云端回放流程：
   App(宇视SDK) → 宇视私有云 → 拉取云端录像 → 本地解码播放

4. 设备控制流程：
   App → 海尔云 → 宇视私有云 → 设备云台控制/布撤防等
```

### 3.3 宇视 SDK 集成方案

#### 3.3.1 SDK 集成范围

| 功能模块 | 说明 | 优先级 |
|---------|------|-------|
| 实时预览 | 实时视频流播放，支持多画面 | P0 |
| 云端回放 | 按时间轴播放云端录像 | P0 |
| 设备管理 | 添加/删除/编辑设备 | P0 |
| 云台控制 | 上下左右/缩放/预置位 | P1 |
| 消息推送 | 移动侦测/人形检测告警推送 | P1 |
| 双向语音 | 设备端与App端语音对讲 | P2 |
| 本地存储回放 | 设备SD卡录像回放 | P2 |

#### 3.3.2 集成注意事项

- **SDK 封装**：在海尔 App 内对宇视 SDK 进行二次封装，隔离直接依赖，为后续替换自研方案预留接口
- **鉴权统一**：用户登录及鉴权走海尔统一账号体系，内部通过 token 映射到宇视平台用户
- **错误处理**：统一错误码映射，将宇视 SDK 错误码转换为海尔 App 标准错误提示

### 3.4 宇视私有云部署方案

#### 3.4.1 部署架构

```
┌─────────────────────────────────────────────────┐
│                 海尔云环境                        │
│  ┌───────────────────────────────────────────┐  │
│  │         宇视私有云（独立VPC/资源池）         │  │
│  │  ┌─────────┐ ┌─────────┐ ┌──────────┐   │  │
│  │  │ 设备管理  │ │ 流媒体   │ │ 云存储    │   │  │
│  │  │ 服务     │ │ 服务     │ │ 服务      │   │  │
│  │  └─────────┘ └─────────┘ └──────────┘   │  │
│  │  ┌─────────┐ ┌─────────┐               │  │
│  │  │ 消息推送  │ │ 用户管理  │               │  │
│  │  │ 服务     │ │ 服务     │               │  │
│  │  └─────────┘ └─────────┘               │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

#### 3.4.2 部署要求

| 项目 | 要求 |
|------|------|
| 网络隔离 | 宇视私有云部署在独立 VPC，通过海尔 API 网关对外暴露接口 |
| 数据安全 | 用户数据、录像数据存储在海尔云内，宇视不可远程访问 |
| 资源预估 | 初期支持 10 万设备接入，按需弹性扩容 |
| 高可用 | 核心服务多副本部署，SLA ≥ 99.9% |

## 四、Phase 2：混合并行方案（3~12个月）

### 4.1 目标

在 Phase 1 稳定运行的基础上，启动海尔自研音视频平台的开发，并逐步将新设备接入自研平台，实现双平台并行运行。

### 4.2 架构演进

```
┌──────────────┐     ┌──────────────────────────────────────┐
│  海尔智家 App  │────▶│           海尔云平台（统一接入层）        │
│  (统一播放SDK) │     │  ┌────────────┐   ┌────────────┐    │
└──────────────┘     │  │ 宇视私有云    │   │ 海尔自研     │    │
                     │  │ (存量设备)    │   │ 音视频平台   │    │
                     │  └────────────┘   └────────────┘    │
                     └──────────────────────────────────────┘
                              │                    │
                     ┌────────▼────────┐  ┌───────▼────────┐
                     │  宇视摄像机(存量)  │  │  新增设备(自研)  │
                     └─────────────────┘  └────────────────┘
```

### 4.3 关键设计

#### 4.3.1 统一接入层

在海尔云平台构建统一接入层（API Gateway），对前端 App 屏蔽后端平台差异：

- **设备路由**：根据设备类型/注册平台，自动将请求路由到宇视私有云或自研平台
- **统一接口**：对外提供标准化的 RESTful API，前端无需感知后端差异
- **统一鉴权**：所有设备接入统一走海尔账号体系鉴权

#### 4.3.2 自研平台核心能力建设

基于宇视提供的源码，重点建设以下能力：

| 能力模块 | 建设内容 | 来源 |
|---------|---------|------|
| 信令服务 | 设备注册、保活、控制信令 | 参考宇视源码自研 |
| 流媒体服务 | 实时流转发、录像回放 | 参考宇视源码自研 |
| 云存储服务 | 录像云端存储、时序索引 | 参考宇视源码自研 |
| 设备管理 | 设备生命周期管理 | 自研（海尔已有基础） |
| 告警服务 | 移动侦测/人形检测告警 | 参考宇视源码自研 |

#### 4.3.3 设备接入策略

- **存量设备**：继续通过宇视私有云接入，不强制迁移，避免用户感知
- **增量设备**：优先接入自研平台，逐步提升自研平台设备占比
- **宇视新设备**：通过宇视提供的设备协议文档，直接接入自研平台

### 4.4 Phase 2 里程碑

| 里程碑 | 时间 | 交付物 |
|-------|------|-------|
| M6：自研平台架构设计 | 第3~4月 | 架构设计文档、接口规范 |

| M8：流媒体服务开发 | 第5~9月 | 实时预览、录像回放功能完成 |

## 五、Phase 3：自研主导方案（12~24个月）

### 5.1 目标

自研音视频平台成熟稳定后，逐步将存量宇视设备迁移至自研平台，最终实现完全自主可控。

### 5.2 架构演进

```
┌──────────────┐     ┌──────────────────────────────────────┐
│  海尔智家 App  │────▶│         海尔自研音视频平台（主力）       │
│  (自研播放SDK) │     │  ┌─────────┐ ┌─────────┐ ┌────────┐│
└──────────────┘     │  │ 信令服务  │ │ 流媒体   │ │ 云存储  ││
                     │  │         │ │ 服务     │ │ 服务   ││
                     │  └─────────┘ └─────────┘ └────────┘│
                     │  ┌─────────┐ ┌─────────┐           │
                     │  │ 告警服务  │ │ AI服务   │           │
                     │  │         │ │         │           │
                     │  └─────────┘ └─────────┘           │
                     └──────────────────────────────────────┘
                              │
                     ┌────────▼────────┐
                     │   全部摄像机设备   │
                     │  (含宇视+自研)    │
                     └─────────────────┘
```

### 5.3 存量设备迁移策略

#### 5.3.1 迁移方式

```
方式一：OTA 渐进式迁移（推荐）
  设备通过固件升级 → 修改注册服务器地址 → 设备重新注册到自研平台
  优点：用户无感知，风险可控
  缺点：需要宇视配合提供固件升级能力

方式二：双注册过渡
  设备同时注册到宇视和自研平台 → 自研平台验证通过 → 切断宇视连接
  优点：可回滚，风险最低
  缺点：设备资源占用增加，运维复杂
```

#### 5.3.2 迁移节奏

| 阶段 | 设备范围 | 迁移方式 | 验证标准 |
|------|---------|---------|---------|
| 第一批 | 1% 存量设备 | OTA 渐进式 | 功能完整、稳定性达标 |
| 第二批 | 10% 存量设备 | OTA 渐进式 | 性能指标达标 |
| 第三批 | 50% 存量设备 | OTA 渐进式 | 全量指标验证 |
| 第四批 | 100% 存量设备 | OTA 渐进式 | 迁移完成 |

### 5.4 自研平台增强方向

| 方向 | 内容 | 价值 |
|------|------|------|
| AI 能力 | 人形检测、人脸识别、行为分析 | 提升产品智能化水平 |
| 边缘计算 | 设备端 AI 推理，降低云端压力 | 降低成本，提升响应速度 |
| 多协议支持 | 兼容更多第三方摄像机品牌 | 扩大设备生态 |
| 开放平台 | 提供 API/SDK 给第三方开发者 | 构建生态壁垒 |

### 5.5 Phase 3 里程碑

| 里程碑 | 时间 | 交付物 |
|-------|------|-------|
| M11：自研平台稳定性达标 | 第12~15月 | 核心指标达到宇视平台同等水平 |
| M12：存量设备迁移启动 | 第15~18月 | 首批存量设备迁移完成 |
| M13：大规模迁移 | 第18~22月 | 80%+ 存量设备迁移完成 |
| M14：宇视私有云下线 | 第22~24月 | 存量迁移完成，宇视私有云资源释放 |

## 六、合作模式建议

### 6.1 合作阶段划分

| 阶段 | 合作模式 | 宇视角色 | 海尔角色 |
|------|---------|---------|---------|
| Phase 1 | 产品交付 | 提供私有云部署 + SDK + 技术支持 | 接入集成、产品运营 |
| Phase 2 | 源码授权 + 技术转移 | 提供核心源码、技术培训 | 基于源码自研平台 |
| Phase 3 | 持续合作 | 持续提供设备固件支持、新设备适配 | 自研平台运营、维护 |

### 6.2 关键合作条款建议

| 条款 | 建议内容 |
|------|---------|
| 源码授权 | 宇视以授权方式提供音视频平台核心源码，海尔享有使用权和修改权 |
| 知识产权 | 基于源码的二次开发成果归海尔所有，宇视保留原始代码知识产权 |
| 设备兼容 | 宇视承诺后续设备固件兼容海尔自研平台协议 |
| 技术支持 | 宇视提供不少于 2 年的技术支持服务，含源码解读、问题排查 |
| 竞业限制 | 双方约定在智能家居监控领域的竞业范围和期限 |

## 七、风险评估与应对

| 风险 | 等级 | 影响 | 应对措施 |
|------|------|------|---------|
| 宇视私有云稳定性问题 | 中 | 影响用户正常使用 | 部署前充分压测，约定 SLA 和应急响应机制 |
| 自研平台开发周期超预期 | 中 | Phase 2/3 延期 | 分模块交付，优先保障核心功能，非核心功能降级 |
| 源码授权谈判不顺利 | 高 | 影响自研平台建设 | 提前启动谈判，明确授权范围和价格，准备备选方案 |
| 存量设备迁移失败 | 中 | 用户设备无法正常使用 | 采用可回滚的迁移策略，分批迁移，预留回退窗口 |
| 宇视后续设备不兼容自研平台 | 高 | 无法实现完全自主 | 在合作协议中明确约定兼容义务，预留协议适配层 |
| 核心技术人员流失 | 中 | 自研平台开发受影响 | 建立知识文档体系，关键岗位设置备份 |

## 九、总结

本方案采用 **"短期快速接入 + 中长期自主可控"** 的分阶段演进策略：

1. **Phase 1（0~3个月）**：通过云云对接方式，快速将宇视设备接入海尔智家 App，满足市场急需
2. **Phase 2（3~12个月）**：在宇视源码支持下，建设海尔自研音视频平台，新设备优先接入自研平台
3. **Phase 3（12~24个月）**：自研平台成熟后，逐步迁移存量设备，最终实现完全自主可控

该方案的核心优势：
