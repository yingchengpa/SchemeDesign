## 设备接口压缩方案 - 协议头命名优化
- 用户反馈协议头字段名 msgtype/compresstype/serialtype/reserved 太长
- 确认用户设计意图：协议头改为"命令字+参数字节"复用结构，cmd=1 时后三字节为 enc/cmp/子类型
- 将协议头 4 字节重命名为 cmd / opt1 / opt2 / opt3
  - cmd=1（业务数据消息）：opt1=enc, opt2=cmp, opt3=子类型
  - 其他 cmd（登录/心跳/停止）：opt1~opt3 置 0 或按需
- 命名用 opt1/2/3 而非 rsv1/2/3，避免与 WebSocket 帧头 RSV1/RSV2/RSV3 混淆
- cmd 枚举改为小数值（1=DATA_MESSAGE, 2=LOGIN, 3=HEARTBEAT...），业务消息统一走 cmd=1
- 同步更新文档 11 处引用 + MEMORY.md

### 后续修正：cmd 语义明确

### enc 细分：CBOR-JSON vs CBOR-Native
- 用户洞察：enc=1(CBOR) 存在两种情况——业务层 JSON 转 CBOR（二进制仍 Base64）vs 业务层直接构造 CBOR（二进制 bstr）
- 用户选定方向B：enc 细分两种 CBOR 模式
- 新 enc 取值：0=JSON, 1=CBOR-JSON(过渡，二进制仍Base64), 2=CBOR-Native(主推，二进制bstr消除膨胀), 3=Protobuf(预留)
- 默认推荐改为 enc=2(CBOR-Native)；过渡 enc=1(CBOR-JSON)；降级 enc=0(JSON)
- 更新 4.3/4.4/4.5.2/4.5.4/4.6.3/4.9.2/5.1/7.3 共 9 处 + MEMORY.md
