# 需求故事

- 需求来源：产品规划
- 需求涉及的设备类型：IPC / NVR / DVR / Server（全部设备类型）
- 需求是否支持国内/海外：ALL（国内 + 海外）
- 是否支持定制：不涉及（通用功能，白牌 / 品牌均支持）

## 需求背景

安防监控系统中，设备离线、录像缺失、硬盘故障等问题直接影响视频证据的可用性和系统合规性。目前用户缺乏统一手段快速掌握所有设备的健康状态，通常需要逐台排查，效率低下且容易遗漏。

本需求旨在为 APP 增加**设备健康报表**功能，让用户一站式查看、统计和导出设备健康数据，快速定位问题设备，保障监控系统持续可靠运行。

## 需求功能点

### 本期实现

**一、基础设备与录像健康（7 项）**

1. 云连接及数据上报状态检测 — 检测 IPC/NVR/VMS 与宇视云的连接状态（当前连接状态、最后在线时间、最后一次数据上报时间、历史云连接在线率）
2. 设备在线状态检测 — 检测 Camera/NVR/DVR/Server 是否在线，支持设备 Uptime 历史统计
3. IPC 视频源检测 — 检查摄像机能否产生图像、是否有实时画面，识别 Feed Outage / Feed Not Live
4. 录像状态检测 — 检查当前是否录像、近期录像是否存在；识别录像异常、配置错误或故障；检查是否在录制音频
5. 录像保存天数检测 — 检查实际保存天数是否达标，识别天数不足或缺失日期的录像
6. 硬盘健康检测 — 检查 NVR/DVR/Server 硬盘状态，显示正常硬盘数量，统计 HDD OK 历史百分比
7. 设备时间与时间戳检测 — 检查设备时钟、视频时间戳和时区，统计与真实时间的 Time Drift

**三、健康展示与统计（7 项）**

8. 当前健康状态汇总 — 汇总摄像机在线数、录像比例、Retention 达标数、硬盘状态、时间状态、画面健康数和问题分类数量
9. 历史健康性能统计 — 按日期范围统计 Device Uptime、Camera Uptime、HDD OK、Cams Live、Recording、Retention、Time Drift 和 Healthy View
10. 按设备和摄像机查看结果 — 支持按 NVR/DVR/Server 查看汇总，支持逐台摄像机查看在线、录像、Retention 和图像健康结果
11. 静音和忽略管理 — 支持将摄像机问题设为 Muted 或 Dismissed，对应时间不纳入历史健康统计
12. 实时健康 Dashboard — 统一 Dashboard 显示设备状态、图像问题、活动告警、历史信息和健康趋势图
13. 自动健康检查 — 系统持续或定期自动检查设备、录像和图像状态
14. 按需健康检查 — 用户手动触发指定设备或摄像机的状态检查

# 我司方案

## 方案对比：云端主动查询 vs 设备主动上报

| 对比维度 | 云端主动查询 | 设备主动上报 |
|----------|-------------|-------------|
| **实时性** | 取决于查询频率，通常为分钟级延迟 | 状态变更立即上报，实时性高 |
| **数据完整性** | 每次查询可获取全量快照，数据完整 | 依赖设备上报触发，可能遗漏中间状态变化 |
| **设备负担** | 云端发起查询，设备被动响应，增加设备请求处理负担 | 设备主动推送，仅在状态变化时上报，日常负担小 |
| **云端负担** | 需要定期轮询所有设备，设备量大时云端压力大 | 仅接收推送，云端压力小 |
| **离线设备处理** | 无法查询离线设备状态，需依赖历史数据 | 设备离线前可上报最后状态，离线后云可标记异常 |
| **网络依赖** | 每次查询需建立连接，网络不稳定时可能失败 | 利用 MQTT 长连接推送，网络抖动容忍度更高 |
| **扩展性** | 新增检测项只需云端调用新接口，无需设备升级 | 新增检测项需设备固件配合升级，迭代周期长 |
| **适用场景** | 适合按需查询、报表生成等非实时场景 | 适合告警通知、实时监控等场景 |

### 推荐方案：混合模式

**设备主动上报（MQTT）为基础** + **云端主动查询（openapi）为补充**

| 数据类型 | 获取方式 | 理由 |
|----------|---------|------|
| 设备在线状态、工作状态 | 设备主动上报 | 状态变化需实时感知，MQTT 推送延迟最低 |
| 硬盘状态、通道状态、电池状态 | 设备主动上报 | 状态变更频率低，上报即可覆盖 |
| 云连接状态、数据上报时间 | 云端自身记录 | 云端已有连接信息，无需向设备查询 |
| 录像状态、录像保存天数 | 云端主动查询 | 需按需获取全量快照用于报表，且需跨多通道汇总 |
| 设备时间 / 时间戳 | 云端主动查询 | 报表生成时按需获取，避免频繁上报 |
| 历史健康统计 | 云端聚合计算 | 基于上报 + 查询数据在云端汇总统计 |

## 交互设计

### 整体页面结构

```
APP 首页
  └─ 设备健康入口（图标/卡片）
       └─ 健康检测主页（H5）
            ├─ Dashboard 总览
            │    ├─ 健康评分（综合打分）
            │    ├─ 在线设备 / 总设备
            │    ├─ 录像正常 / 总通道
            │    ├─ 硬盘正常 / 总硬盘
            │    └─ 问题分类统计（离线 / 录像异常 / 硬盘异常 / 时间异常）
            │
            ├─ 设备列表视图
            │    ├─ 按设备类型筛选（NVR / DVR / Server / IPC）
            │    ├─ 按健康状态筛选（正常 / 异常 / 已忽略）
            │    └─ 逐台设备 → 查看详细健康指标
            │
            ├─ 历史统计
            │    ├─ 日期范围选择
            │    ├─ Device Uptime / Camera Uptime / HDD OK / Recording / Retention / Time Drift 趋势图
            │    └─ 导出报表（PDF / Excel）
            │
            ├─ 静音和忽略管理
            │    └─ 查看已 Muted / Dismissed 的问题列表，支持恢复
            │
            └─ 按需健康检查
                 └─ 手动触发 → 选择设备/摄像机 → 等待检查完成 → 查看结果
```

### 关键交互说明

1. **健康评分**：综合在线率、录像完整率、硬盘健康率、时间准确率加权计算，0-100 分，≥90 绿色 / 60-89 黄色 / <60 红色
2. **问题分类卡片**：点击某类问题（如"录像异常"）可直接跳转筛选后的设备列表
3. **手动检查**：点击"立即检查"按钮，弹窗选择检查范围（全部 / 指定设备 / 指定摄像机），检查期间显示进度，完成后自动刷新结果
4. **导出报表**：支持选择日期范围和导出格式，生成后可在 APP 内预览或分享到第三方应用
5. **静音/忽略**：在设备详情页，对某个异常指标左滑可出现"静音"/"忽略"操作；静音期间该异常不纳入统计，忽略则标记为已知问题

### 设备上报接口

**上报路径**：`LAPI/V1.0/System/Event/Notification/DeviceStatus`

**上报格式**：

```json
{
  "WorkStatus": 0,
  "SystemStatus": {},
  "BatteryNum": 1,
  "BatteryInfoList": [],
  "WifiInfo": {},
  "SIMInfo": {},
  "SIM2Info": {},
  "NetWorkMode": 0,
  "WorkDetails": {},
  "ContainerStatusList": [],
  "ChannelStatusList": [],
  "DeviceAlarmParamInfo": {},
  "GBServerStatus": {}
}
```

| 字段 | 必选 | 类型 | 说明 |
|------|:---:|------|------|
| WorkStatus | O | unsigned long | 工作状态：0-休眠 / 1-工作 / 2-低电量关机 / 3-手动关机 / 4-硬件关机下线 / 5-重置下线 / 6-低电量关机下线 |
| SystemStatus | O | Json Block | 设备系统状态 |
| BatteryNum | M | unsigned long | 电池组个数（从 0 开始） |
| BatteryInfoList | C | array | 电池组状态列表（BatteryNum 非 0 时必选） |
| WifiInfo | O | Json Block | WiFi 状态信息 |
| SIMInfo | O | Json Block | SIM 卡 1 状态信息 |
| SIM2Info | O | Json Block | SIM 卡 2 状态信息 |
| NetWorkMode | O | unsigned long | 网络模式：0-WiFi / 1-有线 / 10-WiFi+有线 |
| WorkDetails | O | Json Block | 设备工作详细状态 |
| ContainerStatusList | O | array | 硬盘/SD 卡状态列表 |
| ChannelStatusList | O | array | 通道状态信息列表 |
| DeviceAlarmParamInfo | O | Json Block | 设备报警参数信息 |
| GBServerStatus | O | Json Block | 国标服务器连接状态 |

## 安全合规设计

### 1. 接口安全

- 所有 openapi 接口必须通过 OAuth 2.0 / Token 鉴权，禁止未鉴权访问
- 接口入参需做合法性校验，防止注入攻击
- 健康数据查询需验证用户对设备的所有权，禁止越权访问他人设备数据
- 报表导出链接设置有效期（建议 24 小时），过期自动失效

### 2. 通信安全

- MQTT 连接使用 TLS 加密，禁止明文传输
- 设备上报数据签名校验，防止伪造上报
- openapi 通信全程 HTTPS

### 3. 数据安全

- 健康报表包含设备运行数据，导出时需加密或限制访问权限
- 历史健康数据保留策略需明确（建议默认 90 天，可配置）
- 不收集用户个人身份信息，无需更新隐私政策

### 4. 端口与监听

- 本需求不新增 TCP/UDP 监听端口
- MQTT 使用已有长连接通道，无新增端口

- 本需求涉及设备运行数据采集，需确保符合当地数据保护法规（国内《个人信息保护法》、海外 GDPR 等）
- 健康检测功能为设备运维性质，不涉及用户个人敏感信息
- 报表导出功能需注意：导出数据仅限设备运行指标，不含用户个人信息
- 海外版本需关注数据跨境传输合规要求，健康数据存储应遵循本地化原则
- 术语使用遵循《产品开发合规指南》中的研发科技伦理术语表，避免使用敏感词
