## 需求背景
宇视云云存服务为 IPC/NVR 设备提供告警图片/视频的云端存储能力。当前设备发生告警时，会将告警图片推送至云端，用户可在 APP 中查看告警记录。但用户面临以下痛点：

1. **告警信息过载**：设备每天产生大量告警图片（如移动侦测、人形检测等），用户需逐条查看才能了解发生了什么，效率低下
2. **缺乏全局视角**：用户无法快速了解一天的告警概况，只能通过时间线逐条翻阅
3. **关键信息难以提取**：用户需要从大量图片中人工提取关键信息（如"有几个人经过""是否有异常事件"等），耗时费力

## 需求功能点
1. **告警图片 AI 描述**：设备告警推送图片时，云端使用多模态大模型对图片/GIF 图进行文本描述，生成自然语言摘要
2. **日维度 GenAI 汇总**：对一天内的所有告警内容进行汇总，生成结构化的日摘要报告
3. **摘要内容展示**：在 APP 中展示 AI 描述和日汇总摘要，支持查看原始告警图片
4. **提示词（Prompt）管理**：设计并维护高质量的提示词模板，确保生成摘要的准确性和一致性

# 我司方案

## 整体设计思路

### 核心架构：实时描述 + 日维度汇总

```
设备告警图片 → [多模态大模型实时描述] → 单条告警 AI 描述
                                                    │
                                                    ▼
                                    [日维度汇总任务（T+1/定时触发）]
                                                    │
                                                    ▼
                                    日摘要报告（自然语言 + 结构化统计）
                                                    │
                                                    ▼
                                            APP 展示
```

**第一层：单条告警 AI 描述（实时）**
- 设备告警图片上传至云存后，触发多模态大模型推理
- 生成单条告警的自然语言描述（如"一名穿黑色外套的男子出现在前门"）
- 描述结果存储并关联告警记录

**第二层：日维度 GenAI 汇总（异步）**
- 每日定时（建议次日 00:30）对前一天所有告警描述进行汇总
- 使用大语言模型将多条描述聚合为结构化日摘要
- 日摘要包含：关键事件统计、异常事件描述、区域安全状态等

## 提示词（Prompt）设计

### 核心设计原则

|| 原则 | 说明 |
| --- | --- |
| 角色明确 | 明确模型角色为"安防监控分析助手"，限定输出领域 |
| 输出格式约束 | 使用 JSON 结构化输出，便于解析和展示 |
| 幻觉控制 | 要求模型仅基于图片内容描述，不推测/推断未出现的信息 |
| 语言风格 | 使用简洁、客观的陈述句，避免主观判断 |
| 安全边界 | 不输出涉及个人身份的信息（如人脸特征描述），不输出可能引起恐慌的表述 |

### 提示词模板一：单条告警图片描述

```
你是一名专业的安防监控分析助手。请根据提供的告警图片/GIF，生成一段客观、简洁的描述。

## 要求
1. 仅描述图片中可见的内容，不推测图片之外的信息
2. 描述应包含以下要素（如图片中可见）：
   - 人物：数量、衣着颜色/款式、大致动作（如走动、停留、奔跑）
   - 车辆：数量、颜色、类型（轿车/SUV/货车/快递车等）
   - 物品：明显可见的物品（如包裹、包裹放置动作）
   - 动物：类型、数量、动作
   - 场景：环境描述（如室内/室外、天气、光照）
3. 不描述人脸特征，不进行身份推断
4. 不使用"可疑""危险"等主观判断词汇
5. 使用简洁的陈述句

## 输出格式
请按以下 JSON 格式输出：
```json
{
  "summary": "一段完整的自然语言描述（50字以内）",
  "objects": ["人物", "车辆", "物品", "动物"等标签列表],
  "scene": "场景描述",
  "actions": ["检测到的动作列表"],
  "confidence": "high/medium/low"
}
```

## 示例
输入：一张前门摄像头抓拍的图片，显示一名穿黑色外套的人正在走动
输出：
```json
{
  "summary": "一名穿黑色外套的人在前门区域走动",
  "objects": ["人物"],
  "scene": "前门室外",
  "actions": ["走动"],
  "confidence": "high"
}
```

### 提示词模板二：日维度汇总

```
你是一名专业的安防监控分析助手。请根据以下当日告警记录列表，生成一份结构化的日汇总报告。

## 当日告警记录
{{alert_list}}

## 要求
1. 汇总应包含以下维度：
   - **人物统计**：今日出现的人物总数、衣着特征、出现时间段
   - **车辆统计**：今日出现的车辆总数、类型、颜色
   - **异常事件**：需要关注的异常情况（如长时间停留、反复出现、非正常时段出现）
   - **区域安全状态**：各监控区域的安全评估（正常/需关注）
   - **关键事件**：当日最重要的 3-5 个事件，按重要性排序
2. 使用客观、简洁的描述
3. 不使用"可疑""危险"等主观判断词汇，用"需关注""非常规"替代
4. 不描述人脸特征，不进行身份推断
5. 如果某个区域无告警，应明确标注"无异常"

## 输出格式
请按以下 JSON 格式输出：
```json
{
  "date": "日期",
  "total_alerts": 总告警数,
  "person_summary": {
    "total_count": 人物出现总数,
    "details": "人物特征描述（如'今日出现20名穿黑衣服的人'）",
    "time_periods": ["出现时间段列表"]
  },
  "vehicle_summary": {
    "total_count": 车辆出现总数,
    "details": "车辆特征描述",
    "types": ["车辆类型统计"]
  },
  "key_events": [
    {
      "time": "事件时间",
      "description": "事件描述",
      "importance": "high/medium/low"
    }
  ],
  "area_status": [
    {
      "area": "区域名称",
      "status": "normal/attention",
      "description": "状态描述"
    }
  ],
  "daily_brief": "一段 100 字以内的自然语言日摘要，概括当日整体情况"
}
```

## 详细技术方案

### 多模态大模型选型

| 模型 | 参数量 | 图片理解能力 | 推理速度 | 成本 | 推荐场景 |
| --- | --- | --- | --- | --- | --- |
| GPT-4o | — | ⭐⭐⭐⭐⭐ | 中（~2s/张） | 高 | 高精度需求 |
| Qwen-VL-Max | 72B | ⭐⭐⭐⭐ | 中（~1.5s/张） | 中 | 性价比优选 |
| InternVL2 | 26B/76B | ⭐⭐⭐⭐ | 快（~1s/张） | 中 | 国产部署 |
| GLM-4V | — | ⭐⭐⭐⭐ | 快（~1s/张） | 中 | 国产部署 |

> **推荐**：初期使用 Qwen-VL-Max 或 InternVL2 作为图片描述模型，使用同系列文本模型（如 Qwen2.5-72B）做日维度汇总。后续根据效果和成本优化模型选择。

### 图片预处理

| 步骤 | 说明 | 参数 |
| --- | --- | --- |
| 缩放 | 将原始图片缩放至模型最优输入尺寸 | 长边 ≤ 1024px |
| 格式转换 | 统一为 JPEG/PNG | 质量 85% |
| 大小限制 | 超过限制的图片分块处理 | 单张 ≤ 5MB |
| GIF 处理 | 提取关键帧（首帧+中间帧+末帧） | 最多 5 帧 |

### 日汇总任务调度

```
定时任务（每日 00:30）
    → 查询前一天 00:00~23:59 所有告警记录
    → 按设备 SN 分组
    → 每个设备一个汇总任务
    → 调用 LLM 生成日摘要
    → 存储结果
    → 通过 MQTT 推送通知给 APP
```

## 异常场景处理

| 场景 | 处理策略 |
| --- | --- |
| 大模型推理超时（>10s） | 返回 pending 状态，进入重试队列，最多重试 3 次 |
| 大模型返回格式错误 | 解析失败时记录原始输出，使用正则提取有效信息，标记为 low confidence |
| 单日告警量过大（>1000条） | 分批处理：先按时间段（每2小时）汇总，再合并为日摘要，避免超出模型上下文窗口 |
| 告警图片模糊/损坏 | AI 描述标记 confidence=low，日摘要中标注"部分图片质量较差" |
| 日摘要生成失败 | 重试 3 次后标记为 failed，不影响单条描述展示；用户可手动触发重新生成 |
| 大模型服务不可用 | 降级为仅展示原始告警图片，AI 描述显示"暂不可用"，服务恢复后异步补生成 |
| 海外多语言需求 | 根据 language 配置，在提示词中指定输出语言；模型输出后不做二次翻译 |

## 安全合规设计

1、对外接口是否有增加异常保护，是否有未鉴权等安全风险。

- AI 描述和日摘要查询接口需鉴权，仅设备所有者可查询
- AI 描述配置接口需鉴权，仅管理员/设备所有者可修改
- 防止恶意大量请求导致大模型推理成本爆炸，需增加接口限流（每用户每分钟 30 次）

2、是否新增监听TCP/UDP端口、端口和业务接口鉴权安全机制、强密码、敏感信息加密传输和保存、Web应用安全、日志和配置安全。

- 本需求不新增对外监听端口
- 告警图片 URL 使用临时签名链接，有效期 1 小时
- AI 描述结果中不包含人脸特征等敏感个人信息

3、是否新增收集个人信息及隐私政策是否需要更新。

- AI 描述功能涉及对告警图片的内容分析，属于数据处理行为，需在隐私政策中明示
- 告警图片本身为用户已有数据，AI 描述为对已有数据的加工，不新增个人信息收集
- 但需确认：
  - AI 描述功能默认开启还是默认关闭？**建议默认开启，用户可关闭**
  - 隐私政策需更新：新增"AI 智能描述"功能说明，说明图片将被多模态大模型分析
  - 海外版本需遵守 GDPR，需提供数据删除能力（删除 AI 描述数据）
  - 大模型推理是否使用第三方 API？若使用，需在隐私政策中说明数据可能传输至第三方

本需求涉及 AI 生成内容，需注意以下合规要点：

1. **AI 生成内容标识**：AI 描述和日摘要应标注"由 AI 生成"，符合《生成式人工智能服务管理暂行办法》要求
2. **敏感词过滤**：AI 描述输出需经过敏感词过滤，避免生成不当内容
3. **避免人脸描述**：提示词已约束不描述人脸特征，不进行身份推断
4. **避免主观判断**：提示词已约束不使用"可疑""危险"等词汇，使用"需关注""非常规"替代
5. **数据本地化**：海外版本需确保数据处理在本地完成，不跨境传输
